Architecture

Screen capture → OCR/CV → Ollama LLM → Mem0 + ChromaDB → Desktop overlay

Omnitrix is a loop: observe the screen, extract structured context, reason with a local model, persist what matters, and surface answers in a lightweight overlay — all without sending pixels to a third party.

  • Active-window capture — context without copy-paste
  • OCR/CV preprocessing before text hits the model
  • Streaming Ollama responses with tool-style prompts
  • Vector memory for habits, preferences, and prior sessions
  • Tray + hotkeys — summon help without leaving your flow

Privacy First

Cloud assistants train on your data; Omnitrix doesn’t leave your machine. Built for students, developers, and anyone who lives in IDEs and browsers all day.

  • No OpenAI / Anthropic keys — Ollama runs locally
  • Screen data processed in-process, not uploaded
  • Embeddings & logs on disk you own and can wipe
  • Offline-capable once models are pulled

Build Log

Solo project · active dev since Mar 2026

Tone.

Behavioral Drift Detector for LLM Outputs · Personal Product

Aug 2026 – Present · Live in production

Continuous probes · Embedding MMD · Token KL · Persona cosine

The Problem

Deployed LLMs don’t fail loudly — they drift. A system-prompt tweak, a model swap, or a poisoned instruction can make tone colder, facts wrong, or persona hijacked while the API still returns 200s. Tone treats that as an observability problem.

  • Probe library across tone / fact / persona categories
  • Baseline distribution vs live samples on a schedule
  • Weighted drift score with configurable alert thresholds
  • “Poison system prompt” demo to prove the detector fires

Architecture

OpenAI-compatible LLM → Sampler → Embedder → ChromaDB → Drift Detector → Dashboard

  • Sampler — scheduled + on-demand probe cycles against any OpenAI-compatible endpoint
  • Embedder — all-MiniLM-L6-v2 vectors stored in ChromaDB
  • Detector — MMD (RBF), token KL divergence, sliding-window cosine
  • Product layer — JWT + Google OAuth, encrypted API keys, per-user isolation

Shipped to Production

Solo build · custom domain · Railway

  • React + Recharts dashboard: drift timeline, category heatmap, baseline vs current
  • FastAPI jobs API so long sample/baseline runs don’t die on proxy timeouts
  • Connect any OpenAI-compatible API (OpenAI, Groq, OpenRouter, Ollama, …)
  • Live at tonehq.xyz with api.tonehq.xyz

Three Signals, One Score

Drift isn’t one number from one trick — Tone runs three complementary checks and combines them so a single noisy metric can’t hide a real personality or factual shift.

  • MMD — distribution distance in embedding space vs the baseline corpus
  • KL — token-distribution shift between baseline and live text
  • Cosine — nearest-baseline similarity per probe, rolled into category drift
  • PCA explainability panel for “what moved” in embedding space

Product UX

Built like a real monitoring console — not a notebook demo.

  • Auth-gated accounts (email + Google)
  • Background jobs + live progress banner
  • Heatmap + alerts when scores cross threshold

Why It Matters

Same discipline as production data systems: measure the thing that can silently break, surface it early, and make the failure mode demoable.

  • LLM ops / eval adjacent
  • Full-stack from stats → UI → deploy
  • Owns the pipeline end-to-end

Stack & Links

FastAPI · React · TypeScript · sentence-transformers · ChromaDB · Railway · Porkbun DNS · encrypted connection store.

  • OpenAI-compatible clients so one connector covers cloud and local models
  • Job store + cached heatmap so the dashboard stays responsive under load
  • Custom domain cutover with TLS on apex + API subdomain

Game Physics · Personal

Jun – Sep 2024

Custom Engine

A from-scratch Pygame mini-golf sim — no Box2D, no middleware. Every bounce, ramp, and sink is hand-tuned collision math running at a locked frame rate.

  • Circle–segment collision with wall normals
  • Friction ramps that accelerate or slow the ball
  • Ricochet angles computed from surface geometry
  • Per-hole stroke limits and win/lose logic
  • Levels defined via coordinate configs — easy to extend

Why It Matters

Shows I understand performance-critical loops, not just CRUD. The same discipline applies to ETL throughput and real-time dashboards.

  • Fixed timestep — deterministic physics ticks
  • Manual integration — velocity, position, restitution
  • Profiling-driven optimization for smooth frames
Performance

60 FPS locked throughout — rendering, collision checks, and scoring update every frame with no dropped ticks.
