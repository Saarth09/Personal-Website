Omnitrix

Flagship Side Project · Personal AI Assistant

Mar 2026 – Present · Active development

On-device · Zero cloud · Always-on

Architecture

Screen capture → OCR/CV → Ollama LLM → Mem0 + ChromaDB → Desktop overlay

Omnitrix is a loop: observe the screen, extract structured context, reason with a local model, persist what matters, and surface answers in a lightweight overlay — all without sending pixels to a third party.

  • Active-window capture — context without copy-paste
  • OCR/CV preprocessing before text hits the model
  • Streaming Ollama responses with tool-style prompts
  • Vector memory for habits, preferences, and prior sessions
  • Tray + hotkeys — summon help without leaving your flow

Privacy First

Cloud assistants train on your data; Omnitrix doesn’t leave your machine. Built for students, developers, and anyone who lives in IDEs and browsers all day.

  • No OpenAI / Anthropic keys — Ollama runs locally
  • Screen data processed in-process, not uploaded
  • Embeddings & logs on disk you own and can wipe
  • Offline-capable once models are pulled

Build Log

Solo project · active dev since Mar 2026

  • Shipped: capture loop, OCR pipeline, Ollama integration, system tray
  • In progress: overlay polish, Mem0/Chroma tuning, prompt library
  • Next: per-app profiles, model hot-swap, plugin hooks

Perception

Captures what’s on screen and turns pixels into structured context the model can reason about — titles, UI text, and region-aware OCR.

  • Configurable crop regions per workflow
  • OpenCV denoise, threshold, deskew before OCR
  • Debounced packets — update only when context changes
  • Window metadata fused with extracted text

Reasoning

Ollama runs locally with streaming output — no API latency, no usage caps, no data leaving the machine.

  • Fast vs deep model routing
  • Markdown streamed into overlay
  • Prompt templates per task type

Memory

Mem0 + ChromaDB remember how you work — shortcuts, preferences, and recurring questions across sessions.

  • Short-term session context
  • Long-term habit embeddings
  • Local-only vector storage

Desktop UX

Designed to feel like a comic sidekick in the background — present when needed, invisible when you’re in flow.

  • Global hotkeys with customizable bindings
  • Tray icon: idle, thinking, error states
  • Non-blocking overlay on top of any application
  • Minimal chrome — answers, not another full app window

Mini-Golf Engine

Game Physics · Personal

Jun – Sep 2024

60 FPS · Zero physics middleware

Custom Engine

A from-scratch Pygame mini-golf sim — no Box2D, no middleware. Every bounce, ramp, and sink is hand-tuned collision math running at a locked frame rate.

  • Circle–segment collision with wall normals
  • Friction ramps that accelerate or slow the ball
  • Ricochet angles computed from surface geometry
  • Per-hole stroke limits and win/lose logic
  • Levels defined via coordinate configs — easy to extend

Why It Matters

Shows I understand performance-critical loops, not just CRUD. The same discipline applies to ETL throughput and real-time dashboards.

  • Fixed timestep — deterministic physics ticks
  • Manual integration — velocity, position, restitution
  • Profiling-driven optimization for smooth frames
Performance

60 FPS locked throughout — rendering, collision checks, and scoring update every frame with no dropped ticks.
